Definition Human-Computer Interaction = the study of the design, evaluation, and implementation of interactive computing systems for human use. It is a multidisciplinary field drawing from psychology, design, computer science, and ergonomics. The primary goal is to make systems that people can use naturally, efficiently, and safely . Key Components 👤 Human The user — with their abilities, limitations, cognitive load, and emotional responses. HCI considers how users think, perceive, and act. Psychology · Ergonomics 💻 Computer The system — hardware devices, software applications, operating systems, and the interfaces that expose functionality to users. Hardware · Software · UI 🔁 Interaction The communication channel between user and system — input methods (keyboard, touch, voice) and output (screen, sound, haptics). Input · Output · Feedback Goals of HCI ✅ Usability ⚡ Efficiency 🎯 Effectiveness 🛡️ Safety 📘 Learnability 🧠 Memorability Usability — How easy and pleasant is the system to use? Efficiency — Can users achieve tasks quickly with minimal effort? Effectiveness — Can users complete their goals accurately? Safety — Does the system prevent dangerous errors? Learnability — How quickly can a new user learn the system? Memorability — After a break, can users easily return and use it? Why HCI Matters Improves user experience — People enjoy using well-designed products. Reduces errors — Good design prevents costly or dangerous mistakes. Increases productivity — Intuitive interfaces let users work faster. Accessibility — Good HCI makes technology usable by everyone, including people with disabilities. Jakob Nielsen (1990) defined 10 general principles for user interface design. These are called heuristics because they are broad rules of thumb, not specific guidelines. 1 Visibility of System Status Always keep users informed about what is happening through appropriate feedback within a reasonable time. Example: A progress bar showing file upload status (12% complete…) Feedback · Transparency 2 Match Between System and Real World Use language and concepts familiar to the user — not system-oriented jargon. Follow real-world conventions. Example: A trash/recycle bin icon on the desktop resembles a real trash can. Language · Metaphor 3 User Control and Freedom Users often choose actions by mistake. Provide a clearly marked "emergency exit" — undo and redo support. Example: Ctrl+Z (Undo) lets you reverse any mistake in a document. Undo · Redo · Exit 4 Consistency and Standards Users should not have to wonder whether different words, situations, or actions mean the same thing. Follow platform conventions. Example: "Save" always means the same thing across all apps (not "Store" or "Keep"). Uniformity · Conventions 5 Error Prevention Better than good error messages is a design that prevents problems from occurring in the first place. Example: A "Confirm before delete" dialog box stops accidental deletion. Prevention · Constraints 6 Recognition Rather Than Recall Minimize the user's memory load. Make objects, actions, and options visible so users don't have to remember information. Example: Dropdown menus show all options (recognize) vs. typing commands from memory (recall). Memory · Visibility 7 Flexibility and Efficiency of Use Accelerators — unseen by novice users — let experts speed up interaction. Serve both novice and expert users. Example: Keyboard shortcuts (Ctrl+C, Ctrl+V) for expert users; menus for novices. Shortcuts · Experts · Novices 8 Aesthetic and Minimalist Design Dialogs should not contain irrelevant or rarely needed information. Every extra unit of information competes with relevant information. Example: Google Search homepage has just a search box — no clutter. Simplicity · Focus 9 Help Users Recognize, Diagnose, and Recover from Errors Error messages should be expressed in plain language (no error codes), indicate the problem, and suggest a solution. Example: "Page not found. Check the URL or go back to Home." not "Error 404". Error Messages · Recovery 10 Help and Documentation Even though it's better if the system is usable without documentation, it may be necessary to provide help. It should be easy to search and focused on the user's task. Example: A searchable FAQ or in-app chatbot assistance. Documentation · Support
